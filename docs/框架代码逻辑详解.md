## 三、逐文件代码讲解

### 3.1 `pytest.ini` — 框架入口配置

```ini
[pytest]
testpaths = cases                    # 只扫描 cases/ 目录
python_files = test_*.py             # 测试文件命名规范
python_classes = Test*               # 测试类命名规范
python_functions = test_*            # 测试方法命名规范
pythonpath = .                       # 将当前目录加入 Python 路径
```

**工作原理**：当你执行 `pytest` 时，pytest 会：
1. 读取 `pytest.ini`
2. 根据 `pythonpath = .` 把 `tests/` 加到 `sys.path`
3. 扫描 `cases/` 下所有 `test_*.py` 文件
4. 找到 `Test*` 类中的 `test_*` 方法
5. 以 `function` 级别 fixture 为每个测试创建隔离的浏览器实例

`addopts` 中的 `--alluredir` 告诉 Allure 把报告数据写入 `reports/allure-results/`。
`--strict-markers` 要求所有 `@pytest.mark.xxx` 必须在 `markers` 列表中声明，防止拼写错误。

### 3.3 `utils/logger.py` — 双通道日志

```python
from logging.handlers import TimedRotatingFileHandler

def get_logger(name="yunshop_test"):
    logger = logging.getLogger(name)
    logger.setLevel(logging.DEBUG)

    # 通道 1: 控制台（INFO 级别，测试时实时查看）
    console = logging.StreamHandler(sys.stdout)
    console.setLevel(logging.INFO)

    # 通道 2: 文件（DEBUG 级别，每日归档保留 7 天）
    file_handler = TimedRotatingFileHandler(
        filename=os.path.join(LOG_DIR, "test_run.log"),
        when="midnight",       # 每天午夜切割
        interval=1,            # 每 1 天
        backupCount=7,         # 保留最近 7 天
        encoding="utf-8",
    )
```

**设计要点**：
- `if logger.handlers: return logger` — 防止重复添加 handler（pytest 可能多次导入模块）
- 控制台用 INFO（简洁），文件用 DEBUG（完整），排查问题时翻文件
- `TimedRotatingFileHandler` 自动归档：`test_run.log` → `test_run.log.2026-06-23`

### 3.5 `conftest.py`（根级）— pytest 生命周期管理

这是整个框架的**启动引擎**，按生命周期分为 4 个阶段：

#### 阶段一：pytest 启动时（`pytest_configure`）

```python
def pytest_configure(config):
    # 创建 Allure 环境信息文件
    env_file.write("Browser=chrome\n")
    env_file.write("BaseURL=http://localhost:3000\n")
```

生成的 `environment.properties` 会在 Allure 报告的 Overview 页面显示。

#### 阶段二：会话开始/结束（`pytest_sessionstart/finish`）

```python
def pytest_sessionstart(session):
    logger.info("云集优选 自动化测试开始")   # 整个测试运行的开始日志

def pytest_sessionfinish(session, exitstatus):
    logger.info("测试结束，退出码: %d", exitstatus)  # 0=全部通过
```

#### 阶段三：driver fixture（核心）

```python
@pytest.fixture(scope="function")
def driver():
    # 1. 创建浏览器
    options = webdriver.ChromeOptions()
    options.add_argument("--window-size=1920,1080")
    service = Service(executable_path=CHROMEDRIVER_PATH)
    drv = webdriver.Chrome(service=service, options=options)
    drv.maximize_window()
    drv.implicitly_wait(10)

    yield drv    # 2. 交给测试用例使用

    drv.quit()   # 3. 测试结束，关闭浏览器
```

**`scope="function"` 的含义**：每个测试方法都会创建一个全新浏览器实例，测试之间完全隔离。

**`yield` 的含义**：
```
创建 driver ──→ yield 交出控制权 ──→ 测试用例执行 ──→ 回到 yield 之后 ──→ driver.quit()
```

#### 阶段四：失败自动截图（`pytest_runtest_makereport`）

```python
@pytest.hookimpl(tryfirst=True, hookwrapper=True)
def pytest_runtest_makereport(item, call):
    outcome = yield               # 等待测试执行完
    report = outcome.get_result()

    if report.when == "call" and report.failed:  # 测试失败了
        driver = item.funcargs.get("driver")      # 拿到当前测试的 driver
        driver.save_screenshot(filepath)           # 截图
        allure.attach.file(...)                    # 附加到 Allure 报告
        allure.attach(driver.get_log("browser"))   # 附加浏览器控制台日志
```

### 3.6 `pages/base_page.py` — 框架灵魂（最重要的文件）

这个文件封装了 Selenium 的所有底层操作，全框架所有 Page Object 都继承它。
需要理解的核心设计理念：

#### 设计理念一：构造函数一次性创建等待器

```python
class BasePage:
    def __init__(self, driver, timeout=None):
        self.driver = driver
        self.timeout = timeout or EXPLICIT_WAIT  # 默认 15 秒
        self.wait = WebDriverWait(driver, self.timeout)
```

`self.wait` 在整个页面对象生命周期内复用，不需要每次查找都创建新的 `WebDriverWait`。

#### 设计理念二：元素定位用元组传参

```python
# 定位器是 (By.策略, "值") 元组，存为类属性
USERNAME_INPUT = (By.CSS_SELECTOR, "input[placeholder*='手机号']")

# 使用时把整个元组传进方法
self.type(self.USERNAME_INPUT, "13800138000")
```

这样做的优势：元素变更只需改一处定位器常量，所有用到的地方自动生效。

#### 设计理念三：所有查找都走显式等待

```python
def find(self, locator, timeout=None):
    wait = WebDriverWait(self.driver, timeout or self.timeout)
    return wait.until(EC.visibility_of_element_located(locator))
```

Selenium 的 `find_element` 是即时查找（找不到立刻报错），而 `WebDriverWait.until` 会轮询等待（最多等 15 秒）。这在页面加载慢、异步渲染时至关重要。

#### 设计理念四：操作方法的层级调用

```python
# 底层：元素查找
def find(self, locator):           ← WebDriverWait + visibility_of_element_located

# 中层：通用操作（所有操作都先调 find）
def click(self, locator):          ← find() → el.click()
def type(self, locator, text):     ← find() → el.clear() → el.send_keys()
def get_text(self, locator):       ← find() → el.text

# 高层：业务操作（在 Page Object 中）
def login(self, username, pwd):    ← type() → click()
```

#### 七大类方法详解

| 类别 | 方法 | 底层 Selenium API | 说明 |
|------|------|-------------------|------|
| **元素查找** | `find(locator)` | `WebDriverWait.until(EC.visibility_of_element_located)` | 等元素可见（最常用） |
| | `find_present(locator)` | `EC.presence_of_element_located` | 等元素在 DOM 中（不要求可见） |
| | `find_all(locator)` | `EC.visibility_of_all_elements_located` | 等所有可见元素 |
| | `is_displayed(locator)` | `try: find() except: False` | 判断可见，不等（3s 短超时） |
| **元素操作** | `click(locator)` | `el.click()` + 拦截重试 | 内置 `ElementClickInterceptedException` 处理 |
| | `click_js(locator)` | `execute_script("arguments[0].click()")` | JS 强制点击 |
| | `type(locator, text)` | `el.clear()` + `el.send_keys()` | 先清空再输入 |
| **内容读取** | `get_text(locator)` | `el.text` | 获取可见文本 |
| | `get_attribute(locator, attr)` | `el.get_attribute(attr)` | 获取任意属性 |
| | `get_value(locator)` | `el.get_attribute("value")` | 获取输入框当前值 |
| **等待** | `wait_for_clickable(locator)` | `EC.element_to_be_clickable` | 等可点击 |
| | `wait_for_invisible(locator)` | `EC.invisibility_of_element_located` | 等消失(loading) |
| | `wait_for_text(locator, text)` | `EC.text_to_be_present_in_element` | 等文本出现 |
| | `wait_for_url_contains(frag)` | `EC.url_contains` | 等 URL 变化 |
| **滚动/鼠标** | `scroll_to(locator)` | `scrollIntoView({block:'center'})` | 滚到居中 |
| | `hover(locator)` | `ActionChains.move_to_element` | 悬停 |
| **选择/弹窗** | `select_by_text/select_by_value` | `Select(el)` | 原生 select |
| | `accept_alert()/dismiss_alert()` | `driver.switch_to.alert` | Alert 处理 |
| **窗口/Frame** | `switch_to_new_window()` | `driver.window_handles[-1]` | 切新窗口 |
| | `switch_to_frame(locator)` | `driver.switch_to.frame` | 切 iframe |
| **截图** | `screenshot(filename)` | `driver.save_screenshot` | 保存到 reports/screenshots |

### 3.7 `pages/front/login_page.py` — Page Object 实例

```python
class LoginPage(BasePage):
    URL = f"{BASE_URL}/login"

    # 元素定位器——全在类属性中定义
    USERNAME_INPUT = (By.CSS_SELECTOR, "input[placeholder*='手机号']")
    PASSWORD_INPUT = (By.CSS_SELECTOR, "input[type='password']")
    SUBMIT_BTN     = (By.CSS_SELECTOR, "button.submit-btn")

    def open(self):
        super().open(self.URL)              # 调用 BasePage.open()

    def login(self, username, password, captcha="dev"):
        self.type(self.USERNAME_INPUT, username)   # 调用 BasePage.type()
        self.type(self.PASSWORD_INPUT, password)
        self.click(self.CAPTCHA_BTN)               # 调用 BasePage.click()
        self._pause(0.5)                           # 短暂等待验证码请求
        self.type(self.CAPTCHA_INPUT, captcha)
        self.click(self.SUBMIT_BTN)

    def get_form_errors(self):
        errors = self.driver.find_elements(*self.FORM_ERROR)  # 少数场景用原生 API
        return [el.text for el in errors]
```

**关键理解**：Page Object 方法中你看不到 Selenium 原始 API，全是 `self.xxx()` 调用基类封装好的方法。这就是 **Page Object 模式的核心价值**——将 Selenium 的复杂性隔离在 BasePage 中。

### 3.8 `pages/front/home_page.py` — 复杂页面怎么写

首页有分类菜单、Banner 轮播、商品楼层、热门推荐 4 大模块。组织结构：

```python
class HomePage(BasePage):
    URL = BASE_URL + "/"

    # 每个模块的元素独立成组
    # ── 分类菜单 ──
    CAT_ITEMS = (By.CSS_SELECTOR, ".cat-item")
    CAT_POPUP = (By.CSS_SELECTOR, ".category-popup")

    # ── Banner 轮播 ──
    CAROUSEL_TRACK = (By.CSS_SELECTOR, ".carousel-track")

    # ── 商品楼层 ──
    FLOORS = (By.CSS_SELECTOR, ".floor")

    # 每个操作封装为独立方法
    def hover_category(self, index):           # 悬停分类
        items = self.find_all(self.CAT_ITEMS)
        self.hover(items[index])

    def click_next_banner(self):               # Banner 下一张
        self.click(self.ARROW_RIGHT)

    def get_floor_goods_count(self, floor_index):  # 楼层商品数
        ...
```

**动态索引模式**：用 CSS `nth-child` 定位第 N 个元素：
```python
self.hover((By.CSS_SELECTOR, f".cat-item:nth-child({index + 1})"))
# nth-child 从 1 开始，但 Python 索引从 0 开始，所以 +1
```

### 3.9 `pages/admin/admin_goods_list_page.py` — 后台页面怎么写

后台使用 Element Plus 组件（表格、对话框），与前台的主要区别：

```python
class AdminGoodsListPage(BasePage):
    # 表格行数据读取——绕过 WebDriverWait，用原生 find_elements
    def get_goods_names(self):
        rows = self.find_all(self.TABLE_ROWS)    # 等所有行出现
        for row in rows:
            cells = row.find_elements(*self.TABLE_CELLS)  # 在行内查找
            names.append(cells[1].text)

    # 操作在行内查找按钮
    def click_delete(self, index):
        rows = self.find_all(self.TABLE_ROWS)
        del_btns = rows[index].find_elements(By.XPATH, ".//button[contains(.,'删除')]")
        del_btns[0].click()
        self._pause(0.3)                        # 等 Dialog 弹出
        self.el_dialog_confirm()                 # 点击确认（Element Plus 封装）
```

**XPath 的作用域查找**：`.//button[contains(.,'删除')]` 前面的 `.` 表示只在当前行的上下文内查找，而不是全页面搜索。

### 3.12 `cases/front/test_login.py` — 完整测试用例

```python
@allure.feature("会员登录")            # Allure 报告的一级分类
class TestLogin:

    @allure.story("正常登录")          # Allure 报告的二级分类
    @allure.severity(allure.severity_level.CRITICAL)  # 严重级别
    @pytest.mark.smoke                # 冒烟标记
    @pytest.mark.p0                   # P0 优先级
    def test_login_success(self, login_page, test_user):
        """
        AAA 模式：
        Arrange ─→ login_page.open()
        Act     ─→ login_page.login(...)
        Assert  ─→ assert login_page.wait_for_url_contains(URL_HOME)
        """
        login_page.open()
        assert login_page.is_login_page()

        login_page.login(test_user["mobile"], test_user["password"])

        assert login_page.wait_for_url_contains(URL_HOME, timeout=5)

    # 参数化测试：同一个方法跑 3 次，每次传不同参数
    @pytest.mark.parametrize("field,desc", [
        ("username", "手机号/邮箱"),
        ("password", "密码"),
        ("captcha", "验证码"),
    ])
    def test_login_empty_field_validation(self, login_page, test_user, field, desc):
        login_page.open()
        # 根据 field 参数决定哪个字段为空
        if field == "username":
            login_page.login("", test_user["password"])
        ...
```

### 3.13 `utils/driver_factory.py` — 多浏览器工厂（备用）

```python
def create_driver():
    factories = {"chrome": _create_chrome, "firefox": _create_firefox, "edge": _create_edge}
    return factories[BROWSER]()

def _create_chrome():
    try:
        from webdriver_manager.chrome import ChromeDriverManager  # 自动管理版本
        service = ChromeService(ChromeDriverManager().install())
    except ImportError:
        return webdriver.Chrome()  # 降级：用系统 PATH
```

这是一个**备用模块**，当前 `conftest.py` 直接实例化 Chrome（与 BaseProject 风格一致）。当需要 Firefox/Edge 或 CI 自动管理驱动版本时，可以改为调用 `create_driver()`。

## 四、关键概念速查

### 隐式等待 vs 显式等待

| | 隐式等待 (implicitly_wait) | 显式等待 (WebDriverWait) |
|---|---|---|
| 设置 | `driver.implicitly_wait(10)` | `WebDriverWait(driver, 15).until(condition)` |
| 作用范围 | 全局，整个 driver 生命周期 | 单次查找 |
| 等待什么 | 元素"存在"于 DOM | 可自定义（可见/可点击/文本/消失...） |
| 本框架 | 设 10 秒保底 | BasePage 所有查找都用显式等待 |

### fixture scope 对比

| scope | 创建时机 | 销毁时机 | 适用场景 |
|-------|---------|---------|---------|
| `function` | 每个测试方法前 | 每个测试方法后 | driver、Page Object |
| `class` | 每个测试类前 | 每个测试类后 | 类级别的共享状态 |
| `session` | 整个测试开始前 | 整个测试结束后 | test_user、base_url 等只读数据 |

### `yield` vs `return`

```python
# return — 不会执行后面的代码
@pytest.fixture
def foo():
    return 1   # 只返回，没有清理机会

# yield — 会执行后面的代码（用于清理）
@pytest.fixture
def driver():
    drv = webdriver.Chrome()
    yield drv     # 测试用例执行
    drv.quit()    # ← 这行一定会执行（即使测试挂了）
```
